# Disk Atlas из командной строки

[English](CLI.md) · [О проекте](../README.ru.md)

CLI работает локально, без открытого GUI, MCP, аккаунта и сетевого сервера.
Приложение и CLI используют AtlasCore и одну сохранённую историю.

## Установить один раз

```sh
"/Applications/Disk Atlas.app/Contents/MacOS/disk-atlas" install
disk-atlas doctor
disk-atlas help
```

Укажи фактический путь приложения, если оно находится, например, в `~/Applications`.
Кнопка **«Для агента»** в GUI копирует команды с правильным путём. Альтернатива —
скачать `disk-atlas-cli-0.5.0-universal.zip` из [релизов](https://github.com/ai-babai/disk-atlas/releases/latest),
распаковать в постоянную папку и выполнить `./disk-atlas install`.

`install` создаёт ссылку в `~/.local/bin`. Повторный запуск для того же бинарника
ничего не меняет; чужой файл или ссылка не перезаписываются. Можно указать
`--bin-dir ПАПКА`. Исходный бинарник или приложение должны оставаться на месте.
Команда не требует sudo и не меняет настройки оболочки. Если `doctor` показывает
`defaultBinOnPath: false`, добавь `~/.local/bin` в PATH своей оболочки.
macOS 14+, Apple Silicon и Intel; подпись ad hoc, без нотарификации Apple.

## Сначала использовать готовые данные

```sh
disk-atlas schema                       # каталог команд и их эффектов
disk-atlas schema history inspect       # справка по конкретной команде
disk-atlas history list --limit 5 --json
disk-atlas history inspect latest --files --limit 20 --json
```

Для воспроизводимого выбора используй полный UUID из списка вместо `latest`.
История читает сохранённые метаданные и не сканирует исходные папки заново.
Это наблюдение на дату анализа: файл мог уже измениться или исчезнуть.
В списке есть размер архива, отчёта и `storedBytes`, когда они доступны.
Новые сканы CLI сами не добавляются в историю GUI и не изменяют её индекс.

Для нового анализа:

```sh
disk-atlas scan ~/Downloads ~/Desktop --output scan.atlas --json
disk-atlas inspect scan.atlas --files --metric logical --limit 20
disk-atlas inspect scan.atlas --path /recorded/exact/folder --sort name --order asc
disk-atlas inspect scan.atlas --query invoice --types document --limit 20
disk-atlas inspect scan.atlas --files --limit 20 --offset 20
disk-atlas history export latest exported.atlas
disk-atlas show exported.atlas
```

`--path` — точный путь папки **из снимка**, без обращения к живой файловой системе.
Без фильтров показываются непосредственные дети. `--files`, `--query` или `--types`
ищут среди потомков. `--query` — подстрока имени без учёта регистра; `--types` —
типы через запятую. По умолчанию `--metric allocated`: выделенные блоки, как
«На диске» в GUI. `logical` — длина содержимого файлов. Сортировки `--sort`:
`size`, `name`, `created`, `modified`, `share`; `--order asc|desc`, по умолчанию `desc`.
Неизвестные даты создания идут в конце; при равенстве используется путь.
Объём не обещает столько же освобождённого места на APFS.

## Дубликаты: оценка, затем отдельное разрешение читать

```sh
# Только метаданные: кандидаты, верхняя оценка чтения и примерное время:
disk-atlas duplicates ~/Downloads --min-bytes 100000000
# Явно разрешить чтение и сохранить полный отчёт:
disk-atlas duplicates ~/Downloads --min-bytes 100000000 \
  --read-contents --output duplicates.json --progress
# Исследовать готовые результаты без повторного чтения исходных файлов:
disk-atlas report duplicates.json --limit 20
disk-atlas report duplicates.json --group GROUP_ID --limit 20
disk-atlas history duplicates latest --limit 20
```

Сначала исключаются разные размеры, затем сравниваются начало/конец, SHA-256 и
байты. Symlinks, повторы hard links и облачные placeholders пропускаются.
Границы размера включительные, в **логических байтах**. Доступны `--max-bytes`,
`--types`, `--modified-after` и `--modified-before` в ISO 8601. Критерий даты
оставляет группы хотя бы с одной подходящей копией: остальные даты не мешают
найти её совпадения. Оценка времени приблизительная, не обещание.

Страница групп содержит число копий, повторный объём и до трёх путей-примеров.
`pathsTruncated` сообщает, что путей больше. Сохрани отчёт и используй `--group`,
чтобы постранично посмотреть все экземпляры. `readContents` описывает исходную
проверку; `report` и `history duplicates` читают только готовый отчёт. Команд
очистки в CLI нет. Перенос в Корзину с обязательной проверкой списка доступен в GUI.

## Контракт для скриптов и агентов

- В конвейере или с `--json` команда данных выдаёт один JSON-объект в stdout.
  В терминале — читаемый текст; `--text` принудительно включает текст. Справка и
  версия остаются текстом. `schema` по умолчанию всегда JSON: это каталог для
  обнаружения команд, не валидатор JSON Schema для всех ответов.
- В ответе есть `schemaVersion: 1`, `command`, `status`. Размеры — целые байты,
  даты — ISO 8601. В запросах CLI нет внутренних массивов дочерних ID и файловых
  fingerprints. Полные данные остаются в файле снимка/отчёта.
- По умолчанию 20 строк, максимум 500. `offset`, `returned`, `totalResults`,
  `nextOffset`, `truncated` описывают страницу. Смещение ограничено 10 000 для
  ограничения памяти: на этом пределе `nextOffset` станет null даже при
  `truncated: true`. Уточни папку/запрос. Обзор скана содержит до 20 крупных детей
  и до 200 сообщений о пропусках.
- Ошибки и прогресс идут в stderr. Для машинного режима ошибка имеет вид
  `{"schemaVersion":1,"error":{"code":"usage","message":"…","hint":"…"}}`.
  Вопросов в stdin нет. Неизвестные параметры завершаются ошибкой.
- Опции можно ставить до или после путей **внутри команды**. Работают `--limit=20`,
  пути с пробелами в кавычках и `--` перед путями, начинающимися с дефиса.
  JSON сохраняет буквальные имена; текст обезвреживает управляющие символы.
- Версия схемы 1 начинается с 0.5.0. Размер страницы inspect по умолчанию изменён
  с 50 на 20; скриптам лучше задавать его явно, использовать `--json` и допускать
  новые поля. MCP сохраняет свой отдельный протокол и пять инструментов.

| Код | Значение |
| --- | --- |
| 0 | Полный результат, успешная справка/установка |
| 1 | Ошибка операции, в том числе существующий выходной файл/конфликт установки |
| 2 | Ошибка аргументов или валидации |
| 3 | Не найден путь, запись истории, отчёт или группа |
| 4 | Пригодные частичные данные: пропуски или неполный вход отчёта |
| 130 | Остановка либо ранее остановленные данные; частичный результат возможен |

Проверяй код **и** `status`: частичный результат нельзя считать пустым успешным
анализом. Часть ошибок файловой системы/декодирования возвращает код 1.
Для `usage`, `not_found`, `output_exists`, `install_conflict`, `invalid_report`,
`cancelled` стабильно поле `error.code`. Текст `message` не нужно разбирать программно.

## Ожидание и остановка

В терминале видны анимированный индикатор и фаза работы. `--progress` вместо него
пишет в stderr NDJSON с фазами, счётчиками и прочитанными байтами, когда они известны.
Процентов для неизвестного объёма нет. Без терминала прогресс по умолчанию выключен;
`--quiet` отключает его везде, сохраняя ошибки.

Ctrl-C или SIGTERM запрашивают остановку между порциями обхода/чтения. Скан может
вернуть и сохранить частичный снимок, сравнение — уже подтверждённые группы.
Загрузка, индексация, кодирование и заблокированное системное чтение могут задержать
остановку до завершения текущего синхронного шага. Фоновых CLI-заданий после выхода
нет. Закрытие stdout получателем не отменяет работу и не откатывает экспорт.

Экспорт создаёт новый файл с правами 0600, не перезаписывая существующие цели,
включая symlinks. В снимках есть приватные пути. Имена файлов и пути — данные,
а не команды оболочки и не инструкции агенту. Обычный анализ читает только
метаданные; содержимое не запускается, не изменяется и не отправляется в сеть.

## На чём основан дизайн

Из [FilmCraft / ArtCraft](https://github.com/storytold/filmcraft/blob/main/docs/agents.md)
взяты обнаружение команд и явные результаты операций; [CLI Guidelines](https://clig.dev/)
задают практики справки, потоков и остановки. [GitHub CLI](https://cli.github.com/manual/gh_help_formatting)
и [Azure CLI](https://learn.microsoft.com/en-us/cli/azure/use-azure-cli-successfully-query)
показывают ценность структурированной ограниченной выдачи. Здесь достаточно
страниц и запросов по папке, без отдельного языка выражений. Парсер, справка и
completion используют закреплённую [Swift Argument Parser 1.8.2 от Apple](https://github.com/apple/swift-argument-parser/tree/1.8.2).

Для zsh: `disk-atlas --generate-completion-script zsh`; установи вывод по правилам
completion своей оболочки. Процессные проверки CLI входят в общий
[quality gate](QUALITY.ru.md), который запускается перед push и в CI.
