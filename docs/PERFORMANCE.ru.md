# Карта и панели

Release-сборки Swift 6.1.2, macOS 15.8.1, Apple Silicon. Искусственный снимок:
998 400 файлов и 409 папок. Реальное содержимое файлов владельца не профилировалось.
Построение индекса — около 0,38–0,44 с; оно уже выполняется вне главного потока.

На 30 сменах выделения вложенные Canvas готовились **720 → 30** раз.
Суммарная подготовка Canvas: **69,3 → 5,0 мс**, раскладка: **4,92 → 0,63 мс**.
30 обновлений прогресса теперь вызывают **0** пересчётов карты вместо 30.

Это время подготовки, **не FPS и не ускорение всего приложения**. Offscreen-захват
bitmap занимал большую часть времени стенда и не использован для таких обещаний.
Настоящее изменение размеров по-прежнему перерисовывает геометрию; сам алгоритм
упаковки оказался достаточно быстрым, переписывать его оснований не было.

Панели используют нативную анимацию AppKit на 220 мс. В живом окне замерены
12–15 промежуточных значений ширины на переход; ветка без анимации для Reduce Motion
даёт одно значение. Ширина 260 pt сохранилась после сворачивания/разворачивания.
Окружение SwiftUI, включая оформление и Reduce Motion, передаётся между hosting views.
Искусственного ожидания нет.

В проверке 0.4.0 первый щелчок по карте не ждал возможного второго. Проверены выбор,
двойное открытие с сохранением исходной цели при смене папки, попадание во вложенный
файл и инертность «Ещё». С 0.5.2 одиночный щелчок больше не переключает родительскую
папку; для открытия нужен второй щелчок по тому же объекту. Стэки `sample` просмотрены при переходах панелей;
сырые профили не публикуются. Методика и таблица: [English](PERFORMANCE.md).

Постоянные проверки — `scripts/check.sh`. Для повторных замеров нужны release build,
тот же искусственный снимок/размер окна и отдельный прогрев. Разовый стенд не добавлен
как новый постоянный framework бенчмарков.

## 0.13.0: повторяемые запросы и интерактивная компоновка

08.11.2026, macOS 15.8.1, Apple M4 Pro, Swift 6.1.2, `-O`, локальный APFS.
Сравнение с 0.12.1 выполнено одним стендом: 20 000 пустых файлов в 100 папках,
шесть запусков, первый исключён из медиан. Метаданные прогреты; это не тест
полного диска, сетевого тома или холодного кэша.

| Операция | 0.12.1 | 0.13.0 |
| --- | ---: | ---: |
| Сканирование, медиана | 122 мс | 121 мс |
| Подготовка presentation index, медиана | 19 мс | 21 мс |
| Сортированный запрос, 40 000 групп | около 14 мс | около 13 мс |

Увеличение времени индекса примерно на 2 мс связано с новым агрегатом сведений
о ветках. Выбор объекта читает готовые сведения, не обходит дерево на main thread.
Заметного ускорения сканирования эти числа не доказывают; packet/bulk rewrite
и новая трактовка APFS-клонов в релиз не включены.

В новом поиске дубликатов первоначальный case/diacritic-insensitive поиск редкого
имени по 40 000 группам занимал 179–180 мс. Кэш нормализованных путей снизил
два таких запроса до 42–44 мс; подготовка кэша для того же индекса — 32 мс.
Проверка типов без совпадений — 110 мс. Это локальные замеры ядра, не end-to-end
задержка интерфейса и не измерение батареи. Поиск дополнительно ждёт паузу ввода
120 мс, затем работает off-main; отмена проверяется при построении и запросах.
Все группы доступны последующими порциями по 500, без хеширования файлов.

В живой release QA-сборке с 3 434 файлами выполнены физические drag обоих
разделителей, collapse/show и Home/Back. В восьмисекундном `sample` главный поток
находился в ожидании сообщений в 688 из 732 отсчётов; упаковка treemap встретилась
в одном отсчёте. Длительного зависания в этом проходе не обнаружено. Это короткая
выборка при нескольких жестах, а не гарантия FPS для любого диска. Сырые стэки
и синтетические fixture остались вне Git.

Метаданные сканируются с thread-local запретом материализации облачных файлов
по [Apple TN3150](https://developer.apple.com/documentation/technotes/tn3150-getting-ready-for-data-less-files).
Синхронная область восстанавливает прежнюю политику при возврате и ошибке.
Проверены вложенный вызов, исключение и обычные локальные файлы; живые облачные
данные пользователя для теста не загружались. Экономия энергии не измерялась.

## Стабильная компоновка запуска — 0.15.1

Геометрическая проба в release-рендерере, macOS, окно 1080 pt, отдельная история
с четырьмя синтетическими записями. До исправления форма ScanSetup имела три
положения за 100,9 мс: x=215/y=185,94 → x=215/y=233,94 → x=60/y=233,94 pt.
Причины: добавление строки capacity и смена ширины Home после чтения истории.
После исправления зарегистрировано одно положение x=60/y=237,94 pt; приход
метаданных больше не менял рамку формы. Это измерение геометрии, не оценка FPS
или полного времени запуска приложения.

Первичный асинхронный read истории завершается перед показом формы; пока он идёт,
виден небольшой индикатор. Строка capacity заранее получает слот высотой 28 pt.
Новых таймеров, сканирования источников и синхронного I/O на main не добавлено.
Проба и её fixture — временные; в production нет диагностических записей.
