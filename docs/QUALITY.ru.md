# Единая проверка качества

```sh
scripts/setup-dev.sh   # один раз: проверка инструментов и установка pre-push hook
scripts/check.sh       # тот же запуск локально, в hook и GitHub Actions
```

Нужны Xcode **16.4 (16F6)** / Swift **6.1.2** и Python **3.9–3.14** с `venv`/`ensurepip`.
Без глобальной установки pip-пакетов, Homebrew,
платных сервисов, аккаунтов и ключей. При нескольких Xcode укажи `DEVELOPER_DIR`.
Первая quality-команда создаёт приватное окружение `.build/quality-tools`:
скачиваются только точные macOS wheels с проверкой SHA-256 из
[requirements.txt](../quality/requirements.txt), включая транзитивные зависимости.
Окружение переиспользуется до изменения списка пакетов или версии Python.
Сборке и упаковке эти пакеты не нужны: достаточно stdlib и Xcode.
В CI `/usr/bin` стоит первым: используются Python/Swift выбранного Xcode,
а не независимо обновляемый Homebrew Python runner. Проверка версии остаётся общей.
Формат исправляется через `scripts/format.sh`. База сравнения — merge base с
`origin/main`, явно: `scripts/check.sh --base <commit>`.

Hook блокирует push при ошибке и требует чистый commit, чтобы проверять именно
отправляемый код. Git не включает hooks при клонировании: сначала запусти setup.
Чужой `core.hooksPath` не перезаписывается. В CI выполняется та же команда; отчёт,
LCOV и mutation logs сохраняются как artifacts. Проверку `quality` можно сделать
обязательной в branch rules. Hook сам не запускает ИИ и не переписывает код:
контрибьютор или работающий агент исправляет сбой и повторяет общий запуск.

## Планка и её область

- Строгий `swift-format` для Sources, Tests и Swift-скриптов; Ruff check/format для
  всех Python-скриптов и тестов; ShellCheck/shfmt для всех shell-команд и hook.
  Compiler warnings как ошибки, сборка всех targets.
- Новые/изменённые функции и computed-property blocks в Sources и Swift/Python-скриптах,
  включая их тесты: CC ≤10, cognitive complexity ≤15. Swift измеряет структурный
  SwiftSyntax; Python — Radon и complexipy. Новых исключений для скриптов нет.
- Изменённые исполняемые строки **AtlasCore**: LLVM line coverage ≥80%.
- Отдельно тот же порог покрытия для производственных Python/Swift-скриптов через
  coverage.py/LLVM, включая изменённые imports и entry points.
- Новые/изменённые функции **AtlasCore** и отдельно производственных Python/Swift-скриптов:
  CRAP average <5, max ≤30. Тесты не входят в порог покрытия/CRAP.
- Циклы SwiftPM targets и локальных Python imports: 0; Core не импортирует GUI/CLI,
  производственные скрипты не импортируют тесты.
- Новые точные дубли тел функций от 9 строк отклоняются, файл Sources или скрипта/теста ≤1 000 строк.
- Generated-property тесты сортировки/перестановок/равных ключей/top-K/фильтров,
  поведенческие проверки сохранности файлов и истории.
- Shell — POSIX-обёртки до 12 строк без ветвлений, циклов, функций и цепочек команд
  (проверяется AST shfmt). Логика вынесена в измеряемый Python; передача аргументов,
  рабочей директории и exit code проверяется реальным запуском.
- Четыре Swift-мутации сортировки и три Python-мутации gate должны обнаруживаться
  assertion failures. Ошибка сборки/импорта/окружения не считается пойманным мутантом.

При ошибке — доработка и повторный запуск. Не обходить hook через `--no-verify`,
не повышать пороги и не перегенерировать исключения ради зелёного результата.
Пороги: [policy.json](../quality/policy.json).

## Честные границы измерения

Метрики сложности считаются по SwiftSyntax, а не по словам в комментариях и
строках. Полные правила подсчёта описаны в [English contract](QUALITY.md#measurements-without-false-guarantees).
Это структурная метрика проекта, а не сертификат эквивалентности SonarQube;
семантический анализ рекурсии/графа вызовов не реализован. Есть self-checks анализатора
и его ошибок. Оба Swift-инструмента компилируются и запускаются на временных данных
с реальными LLVM profiles. Python измеряется по AST; хеш тела не зависит от
комментариев и форматирования. Работа верхнего уровня должна находиться в функциях;
`__main__` вызывает входную функцию.

Покрытие Swift берётся из исполняемых строк LLVM LCOV. Для Core форматирование без изменения
синтаксических токенов не создаёт фиктивного diff. Новые файлы учитываются,
отсутствие покрытия функции или записи производственного скрипта — ошибка,
отсутствие исполняемых изменений — N/A, а не 100%.
База, числа, функции и долг доступны в `.build/quality/report.json`.

CRAP = CC² × (1 − coverage)³ + CC. Используется **line coverage как proxy**, не
basis-path coverage. Порог покрытия/CRAP не охватывает SwiftUI/AppKit и CLI:
для них остаются статические проверки, сборка и ручная проверка нативного UI.
7/7 выбранных мутантов — не полный mutation score проекта. Python-мутации защищают
порог покрытия, независимость двух лимитов сложности и проверку отправляемого коммита.
Generated properties проверяют границы порогов и все 512 графов зависимостей из трёх узлов.
Проверки скриптов охватывают чужие install targets, ошибки установки/компиляции,
аргументы, несколько refs, checksums и отсутствие данных аудита. Для shell числового
покрытия/CRAP не заявляется: логика отсутствует, контракт запуска проверяется процессами.
Процессные проверки CLI
проверяют справку, обнаружение команд, страницы, ошибки, права экспорта, явное
чтение дубликатов, сигналы, конфликты установки и совместимость MCP на временных
синтетических данных. CLI собирается до запуска этих проверок.

Первичный аудит `e5f7721` выявил 29 превышений сложности. Пятнадцать обязанностей
с тех пор удалены или переработаны: части карты/инспектора, управление списком, подготовка, статусы и CLI/MCP.
Осталось **13** замороженных исключений в
[legacy.json](../quality/legacy.json). Они действуют только при точном совпадении
старого тела функции. Любая правка теряет исключение. Долг явно виден в отчёте;
зелёный gate изменений не означает соответствия всей исторической кодовой базы.

## Что проверяет reviewer

- **DRY:** одно правило — одно место; совпадение смысла не всегда ловится clone check.
- **KISS:** простейшее ясное решение текущего сценария; низкая метрика сама по себе не доказательство.
- **YAGNI:** настройка/абстракция привязана к существующему требованию.
- **SOLID / SRP:** связная ответственность, ясный контракт и причина изменения;
  полезные глубокие модули вместо множества бессодержательных обёрток.
- Поведение и названия предметной области; явные побочные эффекты, маленькие
  проверяемые шаги рефакторинга, сохранность данных, отмена и ошибки; тяжёлая
  работа вне главного потока.

Это практические вопросы из инженерных принципов, а не список книг и не обещание
автоматически доказать качество архитектуры. В PR — поведение, границы, свойства
и реально выполненные проверки. Источники и определения — в [English contract](QUALITY.md).
